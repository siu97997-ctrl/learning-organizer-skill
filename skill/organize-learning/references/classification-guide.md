# Classification Guide

Use this guide only when the destination handbook has no stable taxonomy or a new topic does not fit.

## Principles

1. Organize by concepts and capabilities, not by apps alone.
2. Prefer five to nine top-level categories that remain useful over time.
3. Put each question in one primary category.
4. Express relationships with prerequisites, related concepts, and next steps.
5. Split a category when it becomes too broad to scan; merge categories that stay sparse.

## Default Cross-Domain Taxonomy

- **Foundations** — terminology, theories, mental models, core principles
- **Methods and Workflows** — repeatable procedures, frameworks, decision processes
- **Tools and Platforms** — software, services, comparisons, operating guidance
- **Building and Practice** — implementation, exercises, projects, experiments
- **Evaluation and Quality** — testing, metrics, verification, failure analysis
- **Safety and Governance** — privacy, permissions, ethics, compliance, risk
- **Career and Application** — portfolios, interviews, role skills, business use
- **Knowledge Management** — note structure, review, retrieval, learning systems

Adapt names to the learner's domain. Reuse an existing equivalent category instead of introducing synonyms.

## Placement Test

For each question, ask:

1. What capability is the learner trying to gain?
2. What concept must be understood before this one?
3. Where would the learner look for this answer six months later?
4. Is this a durable category or merely today's context?

Choose the category that best answers question 3.
